# J813 capped speaker protection

This experimental profile supports the J813 MacBook Air's four internal speaker
channels at 48 kHz with the Aurora audio driver. It targets comfortable everyday
playback. The amplifier ceilings are -24 dB for both woofers and -32 dB for both
tweeters. Keep those limits when using this profile.

The profile requires the kernel speaker-owner and timeout interlocks present in
Aurora Linux #1000/#1048. Testing used Linux
`ad4910ce6ec1aef2b663e9f6fc8af2436a739742`. The daemon remains subject to the
kernel's locks. An expired owner is refused; systemd starts a fresh process under
the existing `Restart=on-failure` policy. Every digital-gain write is rounded down,
capped and read back.

## Feedback and limits

The eight S16 feedback channels are voltage/current pairs for left woofer, right
woofer, left tweeter and right tweeter. On the measured J813 path, left-woofer
voltage lags current by one sample. `current_delay_samples = 1` aligns that pair
for the power calculation; `current_delay_rate = 48000` prevents using that
correction at an unqualified rate. History survives buffer boundaries and is
cleared after capture reinitialization, rate changes and catch-up gaps. The first
unknown current sample is charged at a conservative full-scale bound.

`Globals/max_volume_db` sets the overall ceiling. An optional
`Speaker/<name>/max_volume_db` can only lower it. Invalid delay or ceiling values
are rejected before any mixer controls open. Profiles without these keys retain
zero delay and the previous zero-dB maximum.

The profile uses model-specific physical thermal parameters and conservative
80-degree-C model limits. Physical parameter data was inspected locally; the
public profile contains no Apple DSP code or tuning bundle. Low-level electrical
measurements check the channel mapping, feedback timing and electrical model.
They do not independently measure cone mass, force factor or all thermal
constants. Thermal and mechanical sensitivity calculations are engineering
screening, not measured manufacturing-tolerance limits.

This daemon supplies protection, not desktop routing or equalization. The
listening test used a newly generated speech sample, a 120 Hz high-pass and a
2800 Hz Linkwitz-Riley crossover, with the four playback channels ordered as
listed above. A complete desktop setup also needs matching ALSA/PipeWire routing.
Full macOS loudness, native LSM2 parity, other sample rates and other machine
models are outside this qualification.

## Hardware evidence

The retained qualification has identity-bound console logs, exact source/profile
hashes, raw feedback, microphone recordings and checksum-verified archives.
Recordings and per-device data remain private.

- Low-level frequency sweeps: all four electrical fits passed; left-woofer fit
  error fell from approximately 36% to 2% after the timing correction.
- The actual daemon's per-period power values matched independent float64 replay.
- Six invalid delay declarations and six invalid per-speaker ceiling declarations
  were rejected before controls opened, leaving the mixer unchanged.
- All-zero playback verified all four gain ceilings and automatic relocking when
  the daemon stalled. A fresh process recovered after the expired owner was
  refused. An unqualified sample rate was refused.
- The shared -32 dB speech trial was clear but too quiet. The -24/-32 dB trial was
  explicitly judged clear and comfortable by the operator. Measured woofer
  output rose by 8 dB; tweeter output stayed within 0.02 dB. No digital clipping
  was observed, all five PCMs closed and kernel taint stayed zero.
- Sustained playback and final packaged-source checks are tracked in the
  qualification ledger; do not infer their result from this preliminary list.

For an independently checkable short capture, run the daemon with
`--sense-capture /path/to/new/sense.raw -v`, retaining its output as `daemon.log`.
The diagnostic is exclusive-create and records at most 960,000 frames. Stop the
capture before that limit for complete replay. With NumPy installed, run:

```sh
python3 testing/verify_j813_power.py /path/to/capture J813-POWER-REPLAY.json
```

The resulting JSON reports the capture/log hashes, every checked period, power
error and reset count. It checks feedback processing; it does not by itself
qualify higher volume. Keep the kernel locks, profile limits and readback checks
throughout testing.
